# 쌤글라스(SsamGlass) 학생 개인정보 보호 아키텍처

> 서버 DB·디스크에 학생 실명·출석번호·원본 시험지를 저장하지 않고, 학교/교육청 공식 구글 시트·드라이브에만 분리 보관하는 제로-널리지(Zero-Knowledge) 설계.

**핵심 목표:** 서버 데이터베이스 및 파일 시스템에서 학생의 고유식별정보(실명, 학년/반/번호, 원본 시험지)를 제거하고, 학교/교육청 공식 클라우드 인프라 기반의 분리 보관 아키텍처를 구축.

**상태:** Phase 1~3 전체 구현 완료.

---

## 1. 설계 원칙

### 1-1. 단일 진실 공급원 (SSOT)

학생의 실명은 **오직 교사/학교 소유의 공식 구글 스프레드시트에만 보관**한다. 서버는 구글 시트에서 이름을 읽어올 수 있으나, 이를 서버 DB에 영구 저장하지 않는다.

### 1-2. 서버 영구 저장소의 비식별화 (Zero PII)

쌤글라스 서버 **DB 및 영구 디스크 저장소**(원본 이미지, 크롭 이미지, DB 테이블)에는 학생의 실명, 출석번호, 식별 가능한 인적사항을 일절 저장하지 않는다.

- 서버 세션 저장소에는 로그인 처리 목적으로 실명이 **일시적으로** 보관될 수 있으며, 세션 수명(30분 무활동 타임아웃 또는 로그아웃 시 파기) 동안만 존재한다.
- "서버에 실명이 전혀 없다"가 아니라 "서버 DB 및 영구 디스크 저장소에 실명이 없다"가 정확한 표현이다.

### 1-3. 프론트엔드 실시간 결합 (Client-Side Join)

검수 화면 등에서 필요한 실명 표시는 교사의 개인 PC 브라우저 메모리상에서만 동적으로 결합하여 표시한다. 실명은 구글 시트(SSOT)에서 읽어온 값을 브라우저 세션/메모리에서 사용하며, 서버 DB에서 조회하지 않는다.

---

## 2. 학생 식별: 솔트 기반 해시 (`student_hash`)

출석번호와의 상관관계를 수학적으로 단절시키기 위해, **구글 시트에만 보관되는 학급 비밀 솔트(Class Secret)** 기반 단방향 해시를 사용한다.

```
student_hash = SHA256( Class_Secret_Salt + "_" + Student_Name ).substring(0, 32)
```

**동작 방식:**

1. 학급 생성 시 난수 솔트를 생성하여 **교사의 구글 시트 숨김 셀에만 저장** (서버는 솔트를 모름).
2. 교사 브라우저가 구글 시트에서 명단을 읽어와, 브라우저 내부에서 이름별 `student_hash`를 계산해 매핑 딕셔너리를 구성.
3. 서버 DB는 `{ student_hash, total_score }`만 저장·반환. 교사 브라우저가 렌더링 시 매핑 딕셔너리로 실명을 표시.
4. 서버 침해 사고 발생 시: 해커는 솔트를 모르므로 레인보우 테이블 공격이 불가능하며, 해시값의 실제 주인을 역추적할 수 없음.

**출석번호를 서버 식별자로 쓰지 않는 이유:** `학교명 + 학년/반 + 출석번호`는 출석부·사물함·좌석표 등과 결합 시 즉시 특정 개인을 식별할 수 있어, 단순 출석번호는 개인정보 분리 요건을 충족하지 못함 (개인정보보호법 제2조 제1호 (나)목).

## 3. 시험지 원본 마스킹

### 3-1. 방식: 클라이언트 사전 마스킹 (Inbound Sanitization)

업로드 뷰(키오스크/단일· bulk 업로드)에서 웹캠 또는 업로드 이미지를 캔버스에 그린 뒤, 인적사항 기재란(상단 영역)을 단색으로 마스킹 처리한 이미지만 서버로 전송한다. 서버는 마스킹이 완료된 이미지를 그대로 저장하며, 서버 측 마스킹 처리는 없다.

**블랙아웃 마스킹을 선택한 이유:** 물리적 절삭(Cropping)은 이미지 Y축 좌표를 변경해 검토 화면의 ROI 좌표계(영역 확장 기능)와 불일치를 일으킨다. 블랙아웃 마스킹은 이미지 전체 해상도와 ROI 좌표계를 보존하면서 인적사항란만 파괴한다.

**효과:**
- 서버 디스크에 학생 실명·학번·학교명이 남아있지 않음 (클라이언트에서 이미 제거).
- 평가 마감 시 `originals/`·`crops/` 폴더를 완전 파기.

## 4. 교사 인증 체계

### 4-1. 교육청 공식 구글 계정 강제

교사 개인용 `@gmail.com` 계정에 학생 평가 자료를 보관하는 것은 교육부 「개인정보 보호 기본지침」 상 업무용 자료의 사적 민간 클라우드 보관 금지 위반 소지가 있다. 전국 시·도교육청이 도입한 **Google Workspace for Education 계정**은 교육청과 Google 간 데이터 보호 협약(DPA)이 체결되어 있어 안전하고 합법적이다.

### 4-2. 구현

- 일반 회원가입 폼을 폐지하고, 첫 화면에서 **[교육청/학교 공식 구글 계정으로 시작하기]** 단일 버튼 제공.
- OAuth 콜백 시 이메일 도메인을 엄격히 검증:
  - `@gmail.com`, `@naver.com` 등 개인 상용 메일 차단.
  - 시·도교육청 (`*.go.kr`, `*.o-e.go.kr`), 초·중·고 학교 (`*.es.kr`, `*.ms.kr`, `*.hs.kr`, `*.sc.kr`) 도메인만 허용.
