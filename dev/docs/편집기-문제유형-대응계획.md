# 편집기 문제 유형 대응 계획

> QUESTION_TYPE_SYSTEM.md의 1차 유형 5종 체계와 editor.php의 현행 로직을 일치시키기 위한 수정 계획.
> 이번 단계: **수정 A~D + 1층위 (editor.php composite 정리)**

---

## 배경

QUESTION_TYPE_SYSTEM.md §5.1에 기록된 현행 코드와 문서 간 불일치 지점 중, editor.php에 직접 영향을 주는 문제들:

1. **소문항이 객관식으로 설정됨** — 정답표 파싱에서 단답형 조합이 `subjective`로 분류되고, `buildSubItemEntry`가 `sub_type`을 보존하지 않으며, `bindAnswerKeyToRois`가 null을 `'subjective'`로 폴백함.
2. **복합 다답형(composite) 로직 잔존** — editor.php에 과거 임시 유형이던 `composite` 관련 UI·로직이 넓게 남아있음. QUESTION_TYPE_SYSTEM.md 1차 유형 5종에 `composite`는 없음.
3. **wheel/클릭 시 소문항 ⇄ composite 토글** — `cycleRoiType`이 답안 영역에서 사용자 의도하지 않은 유형 변경을 유발.
4. **sidebar 단답OX 클릭 시 확인 다이얼로그** — 사용자의 명시적 유형 변경인데도 소문항 다수 존재 시 확인 다이얼로그가 흐름을 막음.

## 수정 A~D (Answer Key Parser) — 완료

### 수정 A: `normalizeAnswerEntry` 패턴 B의 단답형 판별 추가 (line 442~480)

- **변경 전:** `(1) 바다 (2) 74%` 같은 단답형 조합이 무조건 `subjective`로 분류됨
- **변경 후:** OX도 기호도 아닌 경우, 짧은 단어·숫자(길이 ≤20, 단어 수 ≤2) 형태인지 확인하여 `short_answer`로 분류. 단, 채점기준에 서술 키워드(쓰시오, 서술, 설명, 까닭, 이유)가 있으면 `subjective` 유지.

### 수정 B: `buildSubItemEntry`의 `sub_type` 보존 (line 578→595)

- **변경 전:** `'sub_type' => null`
- **변경 후:** `'sub_type' => $type` — 호출자가 전달한 유형 정보가 소문항에도 보존됨.

### 수정 C: `bindAnswerKeyToRois` 소문항 `sub_type` null 폴백 수정 (line 663→680)

- **변경 전:** `$r['sub_type'] = $ansInfo['sub_type'] ?? 'subjective';`
- **변경 후:** `$r['sub_type'] = $ansInfo['sub_type'];` — null 폴백 제거 (수정 B와 연계).

### 수정 D: `bindAnswerKeyToRois` `short_answer` 단일 문항 바인딩 분기 추가 (line 689→706)

- **변경 전:** `short_answer` 유형이 어느 분기에도 해당하지 않아 type이 설정되지 않음
- **변경 후:** `elseif ($ansInfo['type'] === 'short_answer')` 분기 추가, `type='short_answer'`, `sub_type=null` 바인딩.
